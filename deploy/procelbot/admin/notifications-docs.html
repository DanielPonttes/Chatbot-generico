01 / CONTEXTO#visao-geral

O que é o Notification Studio?

É uma bancada protegida para simular notificações de eficiência energética. Você escolhe uma persona, um público e uma missão executável; o modelo local gera uma mensagem curta para inspeção no celular.

EntradaCatálogo + contexto fictício
SaídaCandidata pendente
Efeito externoNenhum push é enviado
02 / OPERAÇÃO#fluxo

Fluxo em quatro passos

1

Escolha a voz

Persona define o tom; perfil do público ajusta a abordagem simulada.

2

Selecione a missão

Use apenas missões executáveis, agrupadas por categoria no seletor.

3

Preencha o contexto

Informe valores inventados. Campos obrigatórios aparecem marcados.

4

Gere e revise

Confira a prévia, depois marque a candidata como aprovada ou reprovada.

Atalho: “Gerar cenário aleatório” sorteia persona, perfil, missão, contexto e estado do RAG para explorações rápidas.
03 / FORMULÁRIO#campos

Campos do formulário

Persona do botobrigatório

Personalidade que redige a candidata — por exemplo, motivadora ou provocadora.

Perfil do públicoopcional

Perfil comportamental usado para adaptar o texto ao receptor simulado.

Missão executávelobrigatório

Objetivo da notificação. O seletor mostra somente missões com template técnico mapeado.

Contexto fictíciopor missão

Variáveis que dão evidência ao template, como sala, presença, consumo e recompensa. Cada campo exibe sua explicação e a chave técnica.

Apoio do RAGopcional

Permite usar conteúdo documental local quando o template recomenda. O sorteio aleatório pode alternar esse estado.

Fonte canônicabloqueada

Permanece desativada no laboratório. Nenhum dado de pessoa, sala ou sensor real é consultado pelo formulário.

04 / INTEGRAÇÃO#contrato

Contrato da API

O navegador usa somente os endpoints abaixo. O gateway injeta a chave administrativa no servidor; ela nunca aparece no HTML.

GET /v1/notifications/missionsLista o catálogo e identifica missões executáveis.
POST /v1/notifications/generateO Studio gera e persiste uma candidata enviando use_canonical_context=false; a fonte canônica não é exposta no laboratório.
GET /v1/notifications/savedCarrega a fila de candidatas e seus pareceres.
PATCH /v1/notifications/saved/{id}Registra Aprovada, Reprovada ou Pendente.
05 / GOVERNANÇA#estados

Estados e revisão humana

Pendente

A candidata acabou de ser gerada e aguarda decisão.

Aprovada

O revisor considerou a mensagem adequada para o cenário simulado.

Reprovada

O revisor encontrou problema de conteúdo, tom ou contexto.

Regra: gerar não publica. A etapa de revisão é obrigatória e permanece separada de qualquer entrega real.
06 / LIMITES#seguranca

Segurança e limites conhecidos

  • O painel administrativo fica atrás do Cloudflare Access.
  • Use valores inventados; não cole nomes, IDs ou leituras de pessoas reais.
  • O contexto aceita até 32 chaves e o backend valida os campos exigidos pelo template.
  • A chave da API e os segredos de infraestrutura ficam no servidor e no ambiente de deploy.
  • Para detalhes de payload, respostas e códigos HTTP, consulte o Swagger protegido.
